# Markdown 媒体发布

模型在正文中用绝对工作区路径引用图片 `![说明](/data/image.png)` 和文件 `[文件名](/data/report.pdf)`。只有 `/data/` 下的文件、以及 HTTP(S) 远程图片算作媒体引用；应用路由（如 `/api/...`）、目录、清理后位于 `/data` 之外的路径、带 `#`/`?` 或行号的源码链接都保持为普通链接。行内代码、代码块和未闭合的 Markdown 不触发读取。

`send` 工具保留，但不再向模型暴露 `attachments` 或 `message.attachments`。chat 模式通过正常回复发布当前会话内容；向其他会话发送时必须指定平台和目标，并在平台解析目标别名后再次拒绝当前会话。discuss 模式仍由 `send` 决定是否发言，schedule 保留显式发送能力。

## 各端语义

- **Web / Desktop**：图片在发布时归档，历史消息从归档展示，源文件覆盖或删除后仍可用。文件链接保持 #1367 的语义，点击后在工作区中打开当前文件，不归档、不改写成下载链接。尚未归档的 `/data` 图片（流式输出中，或 discuss 等不归档的消息）显示为在工作区打开的链接，不从应用源请求 `/data`。
- **IM 渠道**：没有工作区，图片和文件链接都在发布时归档，图片按图片发送，文件作为文件上传。只有 IM 会话归档文件链接；Web、Desktop、CLI 会话不读取被链接的文件。
- **CLI 与本地渠道**：原样显示 Markdown，不展开媒体。

## 发布与展示

- `internal/markdownmedia` 使用 Goldmark 解析引用及原文范围，归档内容并生成绑定。此逻辑不在 Agent runtime 内。
- chat 消息持久化时保留原始正文，在现有 metadata 和 message assets 中记录绑定，不新增数据库字段。资产名使用源文件名。UI 投影只把图片引用替换为经过鉴权的媒体地址。
- 含引用的 tool-tail round 带有 message assets，单语句批量写入无法承载，因此改为在同一事务内逐条写入，保持原子性。
- IM 出站在公共 Channel 层把消息展开为有序的正文、图片和文件，再交给各平台既有的格式化、分段和上传实现。媒体放在其所在的顶层 Markdown 块之后发送，正文中的文件链接保留链接文字，避免拆出不成对的强调、列表或表格。
- 最终回复使用该 run 已持久化的快照绑定，不重新读取可能已改变的源文件。discuss、schedule 和跨会话 `send` 由 agent server 侧的 `channelmessaging` 适配器在交给 Channel 前完成归档，因此 split 模式下 Channel 进程无需访问工作区。

## 流式输出

- 正常推流，只暂停「可能成为媒体引用」的片段：未闭合的 `[`、`![`、以及解析后指向媒体的完整链接或图片。普通感叹号、方括号、外部链接和代码不会暂停推流。
- 暂停的片段一旦确定不是媒体引用就立即放行；放行的长文本按平台长度上限分块，不会超过单条消息限制。
- 出现完整媒体引用后，后续正文暂存到最终消息，以保持媒体在正文中的位置。工具调用前的文本段若含媒体引用，会携带到最终消息，并按本次 run 中前序步骤的快照依次绑定。
- 重试（reset）清空所有暂存内容；已推流的文本按分段记录，最终消息只补发尚未推流的部分。同一 stream 重试最终事件时跳过已确认发出的片段。底层平台请求失败时是否已被接受，仍受平台 API 语义限制。
- 不支持图片展示但支持附件的平台降级为文件；不支持附件的平台显示失败提示。部分媒体不可用时继续展示或投递其余内容；显式发送工具返回 `partial=true`，避免模型重发整条消息。

## 安全与资源限制

- 工作区读取限定在 `/data` 内，使用 bridge 的 descriptor-anchored nofollow 读取，不跟随任何符号链接。内核不支持或 seccomp 拦截 `openat2` 时，退回逐级 `O_NOFOLLOW` 打开，同样拒绝 `.`、`..` 和符号链接。
- 远程图片下载限制非公网地址、重定向和下载时长，单张不超过 20 MiB，并按实际字节判断是否为图片，不信任远端 Content-Type 或 URL 扩展名。
- 图片按嗅探出的类型存储；扩展名声称是图片但内容不是的文件按 `application/octet-stream` 存储。SVG 不作为图片发布。
- `ServeMedia` 只允许光栅图片、音视频、PDF 和纯文本内联展示，其余类型（HTML、SVG、脚本、XML 等）一律以附件下载，避免在应用源上执行内容。
- 每条消息最多归档 20 个不同目标，整条消息的归档有 60 秒总时长预算，超出的引用单独失败。底层存储诊断不会进入用户正文。

## 自动化验证

覆盖引用语法及 UTF-8 范围、`/data` 之外路径与目录的排除、引用式链接、代码块排除、文件覆盖和删除后的历史快照、失败隔离、跨 Bot 读取隔离、非公网 URL、图片字节校验、引用数量上限、当前目标别名拦截、部分成功的 RPC 传递、split 传输前归档、流式暂停点判断、reset、分段与多步媒体携带、放行分块、重复最终事件、按块拆分、Web 历史投影只改写图片、tool-tail round 原子写入，以及 bridge 在 openat2 与回退路径下的符号链接、FIFO、目录拒绝。平台名称参数化的公共出站测试不等于各平台真实 API 或 GUI 验收。

真实客户端验收记录在 PR 中。Discord、Telegram 等 IM 渠道需要专用测试 Bot 和会话；自动化测试和 Agent 操作不能替代 Human QA，本文档不表示验收已经通过。
